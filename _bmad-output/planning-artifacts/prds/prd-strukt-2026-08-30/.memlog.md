- (decision by user) MVP scope: 2D structural analysis only (beams, frames, trusses) via the direct stiffness method; 3D (three.js) explicitly deferred post-MVP
- (note by user) Target users: civil engineering students and engineers
- (note by user) Core workflow: user draws structure (place nodes/elements for beams/frames/trusses), applies loads per node (concentrated or distributed), engine solves via stiffness method, app renders BMD/SFD/NFD diagrams
- (note by user) UI direction: canvas/drawing UX inspired by Figma's interaction model (draw, select, panels) but distinct visual identity and purpose
- (event) Reviewed existing codebase: engine/types.ts + store/useStructureStore.ts have a working data model and zustand store skeleton (StructuralNode, StructuralElement, AnalysisResults); engine/stiffness.ts has two stub functions with empty bodies (getLocalStiffnessMatrix, getGlobalStiffnessMatrix); components/canvas, components/panels, utils are empty directories; app/ is still the default Next.js scaffold
- (gap) Naming mismatch in existing code: engine/types.ts StructuralSupport uses PINNED, engine/constants.ts SUPPORTS key uses HINGE for the same concept — unreconciled, flag for architecture phase
- (decision by user) Stakes calibrated as Launch (full rigor); working mode = Coaching path, entry point = Vision + Features (capability-first)
- (note by research-subagent) Competitive digest: professional desktop tools (SAP2000, ETABS, STAAD.Pro, RISA-3D) are expensive and/or outdated UX; browser-based paid tools (SkyCiv, ClearCalcs) exist, SkyCiv is the only one with real student pricing but its free tier is very limited (5 elements/2 supports/3 loads); free calculators (StructureCalcs, Beamsolver, EasyCiv etc.) are bare-bones homework checkers with no teaching scaffolding; OpenSees/Frame3DD are code-first, not visual; Stabileo (lambdaclass, open-source WASM) is the closest technical analog — browser-based direct stiffness method, no Figma-style canvas UX cited anywhere in the space
- (insight by research-subagent) Positioning gap: nobody combines genuinely free-for-students + modern Figma-like canvas UX + browser-native direct-stiffness engine with teaching-oriented UX. That combination is strukt's differentiation angle
- (decision by user) Primary persona for v1: students first, practicing engineers as secondary beneficiaries of the same fast/free experience
- (decision by user) MVP is results-only: no exposed stiffness-method computation steps (no matrix/DOF-assembly view) in v1
- (decision by user) MVP analysis scope kept minimal: point loads + uniformly distributed loads only; fixed/pinned/roller supports only. Trapezoidal/varying loads, applied moments as loads, internal hinges/releases, and support settlements are deferred post-MVP
- (decision by user) Units: both SI and Imperial, user-selectable, for MVP (larger scope accepted: unit conversion needed throughout engine, UI, and diagrams)
- (decision by user) Beam is not a separate StructureType; it is modeled as a special case of Frame (collinear/horizontal). Data model stays TRUSS | FRAME
- (decision by user) Material/section input for v1: catalog picker (standard steel/concrete sections) with manual override of E, area, inertia \u2014 bigger scope than pure manual entry, requires a section-property database/catalog
- (decision by user) Persistence for v1: full user accounts + cloud-saved projects (not just local file/browser storage) \u2014 requires auth + backend storage as part of MVP scope
- (decision by user) Non-Goals for v1 (explicit): not for stamped/certified professional design work; not dynamic/seismic/time-dependent loading (static only); not code-checking or member design (AISC/ACI etc). User emphasized strongly: strukt IS A LEARNING TOOL, NOT FOR PROFESSIONAL USE \u2014 this is a hard framing constraint, not just a soft non-goal
- (decision by user) Solver correctness bar: validated test suite against known textbook/benchmark problems within tight numerical tolerance, required for v1
- (decision by user) Monetization: entirely free for v1, no paid tier
- (decision by user) Scale target for v1: classroom scale, roughly up to ~50 nodes/elements
- (note by user) UJ-1 (Sara, simply supported beam): draws 8m beam via snap-to-grid, sets Hinged supports at both ends via a support dropdown per node, applies three 5kN concentrated loads via a Loads menu, clicks Solve, engine produces results
- (insight) User's own vocabulary calls the support 'Hinged', matching engine/constants.ts SUPPORTS.HINGE naming, not engine/types.ts StructuralSupport 'PINNED' \u2014 supports reconciling the naming mismatch toward 'HINGE/Hinged' terminology at architecture time
- (decision by user) Unstable structures (singular/near-singular stiffness matrix) must be detected and blocked with a specific error message before/at solve time, not silently solved or crashed on
